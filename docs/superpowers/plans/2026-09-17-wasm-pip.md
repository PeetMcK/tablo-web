# Picture-in-picture on the WASM live path — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pop the picture out on the WASM live path, and keep it moving while
the tab is hidden.

**Architecture:** The pop-out already shows a mirror `<video>` fed by
`captureStream()` rather than moving the playing element, so the mirror simply
takes its stream from the canvas when the WASM path is live. Separately, the
presentation loop stops when the main document hides, so `openWasmSurface`
accepts a frame source and the player points it at the pop-out window while
one is open.

**Tech Stack:** TypeScript, React 19, Vitest + Testing Library, jsdom.

**Spec:** `docs/superpowers/specs/2026-09-17-wasm-pip-design.md`

## Global Constraints

- The transcode path must behave exactly as it does today. Every change is
  either additive or selected by `usingWasm`.
- Nothing inside `frontend/src/lib/wasmlive/` changes except where `loop` gets
  its frames (`open.ts`). The worker, audio clock, ring and deinterlacer are
  untouched.
- No element ever crosses documents. The pop-out gets a mirror; the real
  `<video>` and the stage canvas stay in the tab.
- jsdom implements neither `captureStream` nor pointer capture nor layout.
  Test what is decidable — which source was captured, which frame source is
  installed — not pixels.
- `npx tsc --noEmit`, `npx eslint src` and the full suite pass before each
  commit. `eslint` has two pre-existing errors in `VideoPlayer.tsx`
  (`react-hooks/refs`) from other work; do not add a third and do not fix
  those here.
- Ask before committing.

### Task 3: The presentation loop follows the visible window

Skip if Task 0 found frames keep coming while hidden.

**Files:**
- Modify: `frontend/src/lib/wasmlive/open.ts`
- Modify: `frontend/src/components/VideoPlayer.tsx` (pop-out open and close)
- Test: `frontend/src/__tests__/wasmlivePresenter.test.ts` (or a new
  `wasmliveFrameSource.test.ts` if that file is about something else)

**Interfaces:**
- Produces:
  ```ts
  export interface FrameSource {
    request(cb: FrameRequestCallback): number;
    cancel(handle: number): void;
  }
  ```
  `OpenOptions.frames?: FrameSource` (default: the main document)
  `PlaybackSurface.setFrameSource?(next: FrameSource): void`
- Consumes: `pipWindow.current` in `VideoPlayer`.

- [ ] **Step 1: Write the failing test**

```ts
it("takes its frames from the source it was given", async () => {
  // A hidden document runs no animation frames, so a popped-out canvas has to
  // be driven by the window that is actually on screen.
  const home = fakeFrames();
  const away = fakeFrames();
  const surface = await openWasmSurface({ ...opts, frames: home });

  home.flush(3);
  expect(home.ticks).toBe(3);

  surface.setFrameSource!(away);
  home.flush(3);
  away.flush(2);
  expect(home.ticks).toBe(3);        // the old source is let go
  expect(away.ticks).toBe(2);
});
```

`fakeFrames()` returns a `FrameSource` that records callbacks and runs them on
`flush(n)`, so the loop is driven by hand with no display involved.

- [ ] **Step 2: Run it and watch it fail**

Expected: `setFrameSource` is not a function.

- [ ] **Step 3: Implement in `open.ts`**

Default the source, use it in the loop, and allow it to be swapped —
cancelling the outstanding handle on the old source before requesting from the
new one, or the loop runs twice.

```ts
const DOCUMENT_FRAMES: FrameSource = {
  request: (cb) => requestAnimationFrame(cb),
  cancel: (h) => cancelAnimationFrame(h),
};

let frames = options.frames ?? DOCUMENT_FRAMES;
let handle = 0;
const loop = () => { ...; handle = frames.request(loop); };
handle = frames.request(loop);

// on the returned surface:
setFrameSource(next: FrameSource) {
  frames.cancel(handle);
  frames = next;
  handle = frames.request(loop);
}
```

Take care that the failure path (`open.ts:149`) cancels on the *current*
source, not the one captured when the loop was written.

- [ ] **Step 4: Run the test**

Expected: pass. Then `npx vitest run src/__tests__/` for the wasmlive files.

- [ ] **Step 5: Point the surface at the pop-out window**

## What was actually done, 2026-09-17

### Task 0 was not run

The browser extension this session would have measured through is not
connected, so nothing here was measured in the running app. The plan asked for
that measurement precisely so Task 3 would not rest on an assumption, and it
still rests on one:

- **Assumed:** a hidden document suspends `requestAnimationFrame`, so a canvas
  painted by one goes still while the tab is behind something. This is the
  documented behaviour of Chromium and it was measured on 2026-09-16 on
  another page, but not here.
- **Consequence if wrong:** Task 3 is unnecessary rather than harmful. The
  pop-out window is the one on screen either way, so driving the loop from it
  is correct whether or not the tab's own clock would also have run.

Task 4 was not run for the same reason. Nothing below has been seen on a
screen.

### Deviations from the plan, and why

- **The loop bookkeeping moved out of `open.ts`.** The plan put `setFrameSource`
  inline there, which left the one part with a real failure mode — cancelling
  on the outgoing source before requesting from the incoming one — in the only
  file in `wasmlive/` that cannot be unit-tested, since it needs a real Worker,
  AudioContext and WebGL context. It is now `startFrameLoop` in
  `lib/playbackSurface.ts`, beside `FrameSource`, with
  `src/__tests__/frameLoop.test.ts` driving it by hand. `open.ts` keeps only
  its own step.
- **Both player-level tests live in `pipResume.test.tsx`.** The plan sent the
  button test to `playerChrome.test.tsx`, which would have meant a second copy
  of the WASM-path render helper. They are one subject — what popping out does
  — and now one helper.
- **`DOCUMENT_FRAMES` is exported** from `playbackSurface.ts`, so handing the
  loop back is the same operation as handing it away.
